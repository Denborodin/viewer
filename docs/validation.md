# Проверка сборки 0.1.0 — 26 сентября 2026

## Автоматические проверки

Release x64 собран MSVC 19.44 / Windows SDK 10.0.26100.0. Три набора CTest проходят: **106 проверок ядра + 18 графики/COM + 45 JPEG**, ещё одна проверка активации зарегистрированного COM surrogate в пользовательском сеансе Windows.

Отдельно проверена чистая сборка копии исходной поставки: bootstrap использовал включённые архивы зависимостей, CMake собрал все цели, генератор стандартных fixtures и оба набора CTest прошли без установленного генератора RAR. Большие RAR-fixtures в этот минимальный прогон не входят.

Проверено:

* ZIP stored/deflate, ZIP64 с 65 536 служебными записями, ZIP с 10 002 изображениями; дубликаты имён и Unicode внутри архива.
* RAR4/RAR5, solid и nonsolid: небольшие fixtures и восемь архивов по 1 000/10 000 PNG; последовательное чтение, дальний переход и возврат. Для трёх первых изображений solid счётчики подтверждают один Extract и ровно три извлечённых элемента. Завершение и отмена пробуждают приостановленный поток.
* Повреждённый файл изображения, повреждённый каталог ZIP, ошибка CRC содержимого; отказ для пароля и настоящего многотомного RAR.
* Естественная сортировка с длинными числовыми частями; пути длиннее 260 символов; правильное Windows quoting для Unicode, пробелов, кавычек, обратных слешей и спецсимволов.
* JPEG через libjpeg-turbo с резервом WIC; PNG/BMP/GIF/TIFF через WIC; WebP через встроенный libwebp; EXIF JPEG/WebP, sRGB ICC и premultiplied alpha; ограничение декодированных пикселей бюджетом.
* Direct2D и программный снимок окна: кадр шириной 20 000 пикселей, разбивка на текстуры, поворот и боковая лента. Снимки проверены по пикселям; основной снимок окна также просмотрен визуально.
* SQLite: позиции, инвалидирование позиции при изменении identity, закладки. Папка не обходится рекурсивно; изменённое изображение не получает старые байты из кеша.
* LRU диска, удаление устаревшего файла и записи индекса после семи дней, работа RAM-кеша при недоступном дисковом каталоге.
* Быстрые запросы pipeline, переключение источника и закрытие во время работы; результаты маркируются поколением запроса.
* IExplorerCommand: один поддерживаемый объект включён; неподдерживаемый, пустой и множественный выбор скрыты. DLL зависит только от ole32.dll, SHLWAPI.dll и KERNEL32.dll.
* Настоящая регистрация текущего пользователя, повторная регистрация, удаление, перенос в путь с кириллицей / пробелами / `&` / `%`, восстановление исходного пути, неизменность ProgId/Hash стандартных ассоциаций. После проверки зарегистрирован `dist/Viewer` в режиме Development.

В расширенном тестировании найдена и исправлена гонка на границе завершения Extract: новый запрос не должен помечаться выполненным результатом предыдущего. Дополнительно остановка solid распространяется на пропускаемые не-графические элементы за границей предзагрузки.

## Производительность

ПК: AMD Ryzen 7 9800X3D, Windows 11 25H2 (26200.9550). Это не эталонный четырёхъядерный ПК из плана. Тип накопителя инструментально не зафиксирован. Корпус: 1 000 копий синтетического JPEG 2560×1600 с разными именами, примерно 1,7 МБ каждый. Архивы около 1,7 ГБ. Это проверка механики и производительности на синтетических данных, не разнообразный фотоархив.

20 запусков на режим. Каждый запуск получает пустое состояние/кеш Viewer. Кеш ОС не сбрасывается и после начального обращения прогрет. Окно тестового процесса скрыто. Таймер первого рендера начинается в конструкторе App после начальной COM-инициализации и заканчивается после Direct2D EndDraw + DwmFlush; не включает создание процесса и не измеряет задержку физического дисплея. p95 — 19-е значение из 20 после сортировки.

| Метрика p95 | ZIP stored | ZIP deflate |
|---|---:|---:|
| Каталог архива | 1,64 мс | 1,86 мс |
| Первый декодированный кадр, без запуска UI | 28,94 мс | 34,12 мс |
| Инициализация приложения → первый рендер | 191,10 мс | 200,71 мс |
| Выбор подготовленного кадра → EndDraw | 19,04 мс | 18,13 мс |

Базовый чтение+decode запрашивает около 1,83 МБ / 1,81 МБ данных из архива. К моменту первого рендера UI успевает извлечь **3 изображения из 1 000** с учётом предзагрузки, около 5,2 МБ чтения. Полной предварительной распаковки нет. Подготовленные кадры прогреваются шестью переходами перед замером. Числа соответствуют порядку целевых 1 с / 50 мс, но не доказывают эти цели на указанном в плане эталонном оборудовании.

Сырые результаты: `performance.json`. Повтор: `tests/performance.ps1 -Runs 20`. Для расширенного RAR-корпуса: `tests/make-large-rar.ps1 -RarExe <RAR 6.x>` и CTest.

## Ограничения подтверждения

* Видимое появление команды именно в основном меню Проводника и запуск через реальный щелчок не проверены: инструмент управления окном не получил разрешение. Регистрация пакета, его активация COM и правила видимости проверены отдельно. При необходимости обновления меню показано сообщение о повторном входе; Проводник не завершался.
* Физический ввод мыши/клавиатуры, диалог настроек при разных DPI, несколько мониторов и переходы полноэкранного режима требуют пользовательского прогона. Отрисовка и соответствующие обработчики реализованы; исчерпывающая проверка UI не заявляется.
* Не измерены холодный файловый кеш ОС, HDD, эталонный ПК 4 ядра / 16 ГБ, большой разнообразный корпус фотографий и p95 случайных переходов solid. Не проводилось физическое заполнение системного диска или исчерпание памяти ОС; проверены программные лимиты и отказ доступа к дисковому кешу.
* Локальный MSIX подписан тестовым сертификатом. Windows не приняла доверие только текущего пользователя, поэтому использован уже включённый Developer Mode. Получение доверенной публичной подписи и установка на чистой Windows без Developer Mode не завершены.
* Разрешение ограничивается бюджетом; сверхбольшое изображение может отображаться уменьшенным и при масштабе 100%. ICC переводится в sRGB; управление профилем конкретного монитора/HDR не реализовано.
