# Устройство Viewer

`Viewer.exe` содержит Win32 UI и Direct2D renderer. UI не читает архивы и не выполняет декодирование; получает события через `PostMessage`. Последний готовый кадр сохраняется при новом выборе. `sourceToken` отсеивает результаты прежнего источника, `generation` — прежнего выбора или размера окна.

`IImageSource` (`source.h`) возвращает каталог, байты и fingerprint элемента. FolderSource перечисляет только один уровень. ArchiveSource (`archive.cpp`) открывает полную 7z.dll через абсолютный путь с ограниченным поиском зависимостей. ID элемента — его физический индекс, поэтому одинаковые имена не смешиваются. Порядок отображения независим от ID.

Архив передаётся одному выделенному рабочему потоку после чтения каталога. Несолидное чтение вызывает Extract для одного индекса. Для solid передаётся упорядоченный список изображений блока. GetStream ждёт condition_variable, пока физический индекс не попадает в границу текущей потребности. Это сохраняет стек Extract и словарь между последовательными запросами. Промежуточные изображения по пути к дальней странице кешируются. Другой блок, отмена или некешированный возврат прерывают Extract через E_ABORT. Завершение сверяет фактически выданный ID с текущим запросом: новый запрос, пришедший между последним callback и возвратом Extract, не теряется.

ImagePipeline обслуживает текущий кадр, затем +1/+2/-1 относительно направления, затем видимые миниатюры. Для solid миниатюрам доступны только уже извлечённые байты. Декодированные кадры и исходные байты имеют независимые LRU. При быстром выборе отменяются устаревшие задания; сами WIC-вызовы могут закончить текущую неделимую операцию перед обработкой отмены.

RawCache получает примерно 1/3 RAM-бюджета, декодированный LRU — 1/3, отдельный кадр — до 1/6; очередь дисковых записей ограничена 1/12 RAM и 64 МиБ. Оставшееся пространство резервируется для удерживаемого UI кадра, видимых миниатюр и служебных данных. Временные буферы кодеков, каталог архива и словарь 7-Zip не являются управляемым кешем. Лимит GPU ограничивает размер декодируемого кадра с резервом для миниатюр. При росте масштаба кадр декодируется заново в пределах бюджета.

JPEG декодируется libjpeg-turbo 3.2.0 с SIMD и уменьшением DCT 1/2, 1/4 или 1/8. Окончательный масштаб основного кадра задаёт Direct2D; миниатюры уменьшаются до нужных размеров на CPU. Один контекст декодера переиспользуется рабочим потоком. EXIF и ICC обрабатываются и на быстром пути; CMYK/YCCK и неподдерживаемая точность передаются WIC. WIC читает первый кадр остальных форматов и служит резервным JPEG-декодером. libwebp встроен статически; EXIF и ICC читаются через demux. Цвет переводится в sRGB, выход — premultiplied BGRA. Renderer хранит D2D-текстуры текущего кадра частями до 4096×4096; при невозможности создания аппаратного target используется программный. Полное управление цветом конкретного монитора HDR/wide gamut в 0.1 не реализовано.

StateStore использует системную SQLite (`winsqlite3.dll`, Windows 11), WAL и короткие сериализованные запросы. Запись позиции/закладок/настроек — поток pipeline; индекс диска — отдельный поток RawCache. Инициализация БД выполняется при создании окна. SQLite хранится в LocalAppData, пути и строки — Unicode. Fingerprint включает абсолютный путь, ID файла, размер и время изменения.

ViewerShell.dll — отдельный COM-сервер IExplorerCommand, зависит только от системных DLL. GetState проверяет число объектов, расширение и атрибуты файловой системы. Invoke вызывает CreateProcessW с абсолютным Viewer.exe и корректным Windows quoting. Манифест sparse MSIX регистрирует COM surrogate и windows.fileExplorerContextMenus. Register.ps1 управляет только Viewer.Local и собственным сертификатом текущего пользователя; исходные ассоциации не затрагиваются.

PSD: собственный ограниченный парсер сведённого изображения, построчные Raw/PackBits/zlib, усреднение под окно. ICC проходит через WIC; Gray-профиль получает одноканальные входные данные. Слои пропускаются. Подробнее: [psd.md](psd.md).
